## User Scenarios & Testing *(mandatory)*

### User Story 1 - Professional Chat Interface (Priority: P1)

用户通过简洁专业的聊天界面与AI助手交互，界面提供清晰的视觉反馈和直观的操作体验。

**Why this priority**: 聊天界面是用户的主要交互入口，直接影响使用体验。

**Independent Test**: 打开聊天视图，发送消息，验证消息气泡、加载状态、错误提示等UI元素正确渲染。

**Acceptance Scenarios**:

1. **Given** 聊天视图打开, **When** 用户发送消息, **Then** 消息以用户气泡样式显示
2. **Given** AI正在处理, **When** 用户等待, **Then** 显示加载指示器
3. **Given** 发生错误, **When** 消息发送失败, **Then** 显示错误提示和重试按钮
4. **Given** 长对话存在, **When** 打开聊天, **Then** 自动滚动到最新消息
5. **Given** 暂无任何消息, **When** 打开聊天视图, **Then** 显示空白态引导且输入区可用

---

### User Story 2 - Clean Settings Panel (Priority: P1)

用户通过清晰的设置面板配置插件，设置项分组合理，提供实时验证反馈。

**Why this priority**: 正确的配置是插件正常工作的前提。

**Independent Test**: 打开设置面板，修改各项设置，验证验证逻辑和保存功能正常。

**Acceptance Scenarios**:

1. **Given** 设置面板打开, **When** 用户查看, **Then** 设置按逻辑分组显示
2. **Given** 输入无效URL, **When** 尝试保存, **Then** 显示具体错误信息
3. **Given** 点击测试连接, **When** 测试完成, **Then** 显示成功或失败反馈
4. **Given** 模型选择可用, **When** 打开下拉框, **Then** 模型按提供商分组显示

---

### User Story 3 - Chat Toolbar (Priority: P2)

用户可以通过工具栏快速执行常用操作：清空对话。工具栏位于聊天视图顶部，横向排列。

**Why this priority**: 提供便捷的对话管理功能。

**Independent Test**: 使用工具栏按钮，验证清空和新建功能正常工作。

**Acceptance Scenarios**:

1. **Given** 对话存在, **When** 点击清空, **Then** 显示确认对话框
2. **Given** 确认清空, **When** 操作完成, **Then** 消息清空并显示欢迎信息

---

### Edge Cases

- 对话进行中切换服务URL：提示用户需要清空当前对话才能切换URL
- 网络超时或连接缓慢：30秒后自动超时，显示错误提示和重试按钮
- 消息中包含代码块和markdown：渲染代码块、行内代码、粗体、斜体、列表
- 关闭并重新打开聊天视图：完全恢复会话（包括消息历史和后端会话ID）

## Requirements *(mandatory)*

### Functional Requirements

#### Chat Interface
- **FR-001**: 用户消息和AI回复使用不同样式的消息气泡区分
- **FR-002**: AI处理时显示加载指示器
- **FR-003**: 新消息到达时仅在用户位于底部（或接近底部）时自动滚动，否则显示“新消息”提示
- **FR-004**: 支持markdown渲染（代码块、行内代码、粗体、斜体、列表）
- **FR-005**: 消息发送失败时显示错误提示和重试按钮；重试在同一会话中重新发送上一条用户消息（内容不变）
- **FR-006**: 支持Enter发送、Shift+Enter换行
- **FR-018**: 网络请求30秒后自动超时，显示超时错误和重试选项
- **FR-020**: 关闭并重新打开聊天视图时，完全恢复会话（消息历史和会话ID）

#### Settings Interface
- **FR-007**: 设置项按逻辑分组（连接、模型选择）
- **FR-008**: Service URL实时验证仅做格式校验（协议 + host + 端口），显示具体错误
- **FR-009**: 连接测试按钮，显示成功/失败反馈
- **FR-010**: 模型下拉框按提供商分组显示
- **FR-011**: 刷新按钮重新加载可用模型
- **FR-017**: 修改Service URL时，如有活动对话则提示用户需先清空对话

#### Chat Toolbar
- **FR-012**: 提供清空对话按钮，带确认对话框；确认后清空消息并创建新会话（重置会话ID）
- **FR-013**: 清空后显示空白态引导（欢迎标题+一句说明）
- **FR-019**: 工具栏位于聊天视图顶部，按钮横向排列

#### Visual Design
- **FR-014**: 使用Obsidian CSS变量保持风格一致
- **FR-015**: 交互元素提供hover状态
- **FR-016**: 使用简洁图标（发送、清空、刷新）
- **FR-021**: 聊天视图采用专业布局：顶部工具栏含标题与右侧图标按钮，消息区域为卡片式容器
- **FR-022**: 消息气泡具备清晰层级：用户气泡使用强调色，AI气泡使用次级背景并带细边框
- **FR-023**: 输入区为固定底部浮层条，文本框有聚焦描边与轻微阴影，发送按钮为图标按钮
- **FR-024**: 系统提示消息居中且使用弱对比边框（虚线或浅色边框）
- **FR-025**: 空白态显示轻量引导（标题+一句说明），不遮挡输入区
- **FR-026**: 重要操作使用图标按钮+悬浮提示，弱化纯文本按钮
- **FR-027**: 采用轻量阴影与圆角建立层次，避免重度边框
- **FR-028**: 输入区与消息区视觉分离（间距+背景/阴影）
- **FR-029**: 视觉密度适中，默认字号 13-14px，行高 1.5
- **FR-030**: 动效为可选增强（不影响功能验收）

### Typical Chat UI Blueprint (Modern)

#### Layout Structure
- **Top Toolbar**: 左侧标题（如 NoteBuddy Chat），右侧图标按钮区（清空/刷新），保持单行对齐；底部分隔线改为柔和阴影
- **Message Stage**: 中央消息容器，浅层背景+细边框，轻微内阴影，卡片式圆角
- **Composer Bar**: 底部输入区为“浮层条”，与消息区保持间距，输入框与发送按钮左右排列

#### Message Anatomy
- **User Bubble**: 右对齐，强调色背景，文本对比清晰，圆角略小于容器，轻量阴影
- **Assistant Bubble**: 左对齐，次级背景 + 细边框，阅读舒适，顶部留出细微呼吸感
- **System Notice**: 居中，弱对比边框或虚线，内容简短
- **Loading State**: 气泡内出现轻量占位（如三点波动/文本“思考中”）
- **Error State**: 气泡内显示错误信息与重试按钮，错误色仅用于图标/边框
- **Timestamp (optional)**: 低对比、次级文本，默认不显示（本期不加设置项）

#### Visual Hierarchy
- 视觉层级顺序：标题 > 消息容器 > 气泡内容 > 辅助状态
- 强调色仅用于用户气泡与主要操作（发送），避免大面积铺色
- 交互反馈：按钮 hover/active，输入框 focus ring，轻量阴影提升层次
- 动效建议：新消息淡入（150-200ms），加载状态轻量循环

#### Spacing & Sizing (Guidelines)
- 容器内边距：16px
- 气泡间距：8px
- 气泡最大宽度：70%
- 工具栏/输入区高度一致（约 40px）
- 输入区与消息区间距：12px
- 气泡圆角：8-12px
- 消息容器圆角：12-16px

### Key Entities

- **Message**: 聊天消息，包含内容、发送者、时间戳、状态（发送中/已发送/失败）
- **UIState**: 界面状态，包含加载状态、错误信息

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以顺畅地发送消息并收到回复，全程有清晰的视觉反馈
- **SC-002**: 设置面板配置直观，用户能快速完成首次连接配置
- **SC-003**: 界面在light/dark主题下保持与Obsidian风格一致
- **SC-004**: 错误状态提供清晰的提示，用户能自行解决问题

## Assumptions

1. 使用Obsidian内置CSS变量保持风格一致
2. AI回复可能包含markdown格式
3. 消息历史和会话ID在插件运行期间持久化（Obsidian重启后清空）
4. 使用Obsidian内置图标或简单Unicode符号

## Dependencies

- Obsidian API
- 现有OpenCodeClient服务层
- spec 003的模型选择基础设施

## Out of Scope

- 语音输入/输出
- 对话导出功能
- 消息搜索/过滤
- 跨会话持久化
- 移动端优化
- 完整的无障碍支持（WCAG合规）
